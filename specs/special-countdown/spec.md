# SPEC-086 — Таймер акции в карточке товара

**Status:** implemented
**Owner:** Zhuravlev Artem
**Last updated:** 2026-10-28

## Problem

У скидочной цены (`product_special`) в админке можно задать «Дата окончания», но на карточке товара
покупатель этого не видит: нет срочности, акция просто исчезает. Дата сейчас используется только в
структурированных данных (JSON-LD, SPEC-080).

## Purpose

Если у действующей скидочной цены задана дата окончания, в блоке цены карточки товара показывается
таймер обратного отсчёта до конца акции.

## Scope

- Блок таймера под ценой в `product.twig` темы (не в боковой/липкой панели).
- Данные: дата окончания действующей скидки текущей группы клиентов, передаётся в шаблон событием `ocs`.
- Небольшой JS (без библиотек) и стили темы; строки uk-ua / ru-ru / en-gb; пакет темы.

## Out of scope

- Таймер в карточках каталога, модулях, быстром просмотре и в корзине.
- Скидки по количеству (`product_discount`), акции без даты окончания.
- Автоматическая смена цены на витрине по истечении (цену считает сервер при следующей загрузке).

## Functional requirements

- **REQ-TMR-001** — Таймер выводится на странице товара, только если действует скидочная цена (`special`) с непустой `date_end` для текущей группы клиентов и цена видна покупателю.
- **REQ-TMR-002** — Формат: «Акция закончится через: ДД д ЧЧ : ММ : СС» (дни скрываются, если 0), обновление раз в секунду.
- **REQ-TMR-003** — Точное время окончания: 00:00:00 даты `date_end` по часовому поясу магазина (ядро перестаёт применять скидку при `date_end <= NOW()`, таймер совпадает с моментом смены цены); сервер отдаёт оставшиеся секунды и ISO-время, клиент считает по часам браузера от серверного остатка (не зависит от пояса посетителя).
- **REQ-TMR-004** — По достижении нуля блок скрывается без перезагрузки; товар с датой начала в будущем или истёкшей акцией таймера не получает.
- **REQ-TMR-005** — Если дат окончания нет — разметка и JS не выводятся (ничего лишнего в HTML).
- **REQ-TMR-006** — Опция товара/вариации, меняющая цену, таймер не затрагивает (таймер относится к специальной цене товара).

## Non-functional requirements

- **REQ-TMR-010** — Ничего не правится в `core/`; только событие расширения `ocs`, шаблон/стили/JS темы.
- **REQ-TMR-011** — Без лишних запросов: дата берётся одним запросом (уже есть аналогичный в `ldProduct`), без N+1; серверный рендер начального значения — без CLS.
- **REQ-TMR-012** — Доступность: `role="timer"`, видимая подпись, `aria-live="off"` (без озвучки каждую секунду); с `prefers-reduced-motion` без анимаций.
- **REQ-TMR-013** — Строки на uk-ua, ru-ru, en-gb; корректный вид на телефоне.

## Data requirements

Новых таблиц/настроек нет, миграция не нужна: используется `product_special.date_end`.

## Interfaces

- Событие `catalog/view/product/product/before` (в `applyDisplay`, маршрут `product/product`) добавляет `ocs_special_timer` (`{seconds_left, ends_at}` или пусто).
- Шаблон: блок в `custom/theme/ocs/template/product/product.twig` внутри `.ocs-price-box`.
- JS/CSS: `custom/theme/ocs/` (скрипт темы, `stylesheet.css`).

## Edge cases

- `date_end = 0000-00-00` → таймера нет.
- Несколько скидок: берётся действующая с наименьшим приоритетом/ценой (как у ядра `getProduct`).
- Осталось < 1 дня → дни не показываются; ≥ 100 дней → показываются как есть.
- Часы посетителя неверны → отсчёт от серверного остатка, а не от абсолютного времени.

## Acceptance criteria

- [ ] Товар со скидкой и датой окончания показывает таймер под ценой, отсчёт идёт.
- [ ] Товар со скидкой без даты, без скидки, с истёкшей/будущей акцией — без таймера.
- [ ] По нулю таймер исчезает; вид на десктопе и телефоне проверен.
- [ ] `npm run verify` зелёный; архив темы пересобран (`npm run pack:theme`).
