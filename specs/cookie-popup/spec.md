# SPEC-083 — Попап с условиями использования cookie

**Status:** implemented
**Owner:** Zhuravlev Artem
**Last updated:** 2026-10-28

## Problem

Магазин ставит cookie (сессия, валюта, язык, избранное/сравнение, аналитика), но посетителю нигде
не сообщается об этом и нельзя выразить выбор. Нужен стандартный попап «Мы используем cookie»
со ссылкой на условия, управляемый из админки без правки кода.

## Purpose

Модуль `ocs_cookie` (Расширения → Модули): ненавязчивый попап внизу экрана с мультиязычным
текстом, ссылкой на страницу условий и кнопками «Принять» / «Только необходимые». Выбор
запоминается и доступен другим скриптам (задел под `ocs_tags`, SPEC-017).

## Scope

- Расширение `custom/extensions/ocs_cookie/` (admin + catalog, uk-ua / ru-ru / en-gb).
- Вывод в `footer.twig` темы, стили в теме, JS в `theme.js` (или отдельный маленький файл).
- Пакет темы (`npm run pack:theme`), демо-настройки.

## Out of scope

- Реальная блокировка/загрузка сторонних скриптов по категориям (это `ocs_tags`, SPEC-017); здесь
  только сохранение выбора и публичный JS-хук.
- Детальные настройки по категориям (чекбоксы analytics/marketing) — вторая итерация.
- Серверная запись согласий в БД, привязка к клиенту.
- Правки `core/`.

## Functional requirements

- **REQ-CKP-001** — Модуль в Расширения → Модули как «OCS: Попап cookie»; одна глобальная настройка (не слот макета — попап поверх страницы); права `extension/module/ocs_cookie` группе 1.
- **REQ-CKP-002** — Общие настройки: статус; позиция (снизу слева-карточкой / снизу на всю ширину); версия согласия (число; при увеличении попап показывается всем снова); срок хранения выбора в днях (по умолчанию 365).
- **REQ-CKP-003** — На каждый язык: заголовок, текст, подпись ссылки на условия, URL условий (внутренний путь или http/https; `javascript:`/`data:` отбрасываются), подписи кнопок «Принять» и «Только необходимые». Язык без текста → попап для него не выводится.
- **REQ-CKP-004** — Попап показывается, пока нет валидного cookie выбора для текущей версии; обе кнопки равнозначны по виду и размеру; после клика попап закрывается и не появляется снова.
- **REQ-CKP-005** — Выбор хранится в cookie `ocs_consent` (значение `all` | `necessary` + версия, `SameSite=Lax`, `Secure` на https, срок из настроек). Имя совместимо с SPEC-017.
- **REQ-CKP-006** — Публичный JS-хук: `window.ocsConsent.get()` возвращает `{choice, version}` или `null`; при выборе диспатчится событие `ocs:consent` на `document` — чтобы будущие модули тегов могли подписаться.
- **REQ-CKP-007** — Ссылка «Настройки cookie» (необязательная, в футере/по селектору `[data-ocs-cookie-reopen]`) снова открывает попап.
- **REQ-CKP-008** — Попап не вызывает сдвигов макета (CLS): `position: fixed`, серверный рендер скрытым, показ без анимации высоты; на мобильном не перекрывает нижнюю панель вкладок (SPEC-042) — поднимается над ней.

## Non-functional requirements

- **REQ-CKP-010** — Ничего не правится в `core/`; только расширение, правка шаблона темы, миграция.
- **REQ-CKP-011** — Пользовательский текст экранируется при выводе (Twig autoescape OFF); URL проходят `safeUrl`.
- **REQ-CKP-012** — Без доп. запросов к БД: настройки из `setting`; JS без зависимостей и без сетевых запросов.
- **REQ-CKP-013** — Доступность: `role="dialog"`, `aria-labelledby`, фокус на кнопке «Принять» не отбирается у страницы принудительно (не модальный, без блокировки скролла), фокус-стили, перевод на uk-ua, ru-ru, en-gb.
- **REQ-CKP-014** — Совместимость с full-page cache (SPEC-019): попап в HTML всегда, показ решает JS по cookie.

## Data requirements

Глобальные настройки в `setting` (`code = module_ocs_cookie`): `module_ocs_cookie_status`,
`_position`, `_version`, `_days`, `_l` (JSON: `{lang_code: {title, text, link_label, link_url,
accept, necessary}}`). Миграция `001_install.php` регистрирует расширение, права, дефолты
(статус 0, тексты по умолчанию на трёх языках). Новых таблиц нет. Cookie `ocs_consent` — только на клиенте.

## Interfaces

- Admin: `extension/module/ocs_cookie` (форма с вкладками языков).
- Catalog: событие `catalog/view/common/footer/before` добавляет `ocs_cookie` в данные футера; класс `system/library/ocs/cookie.php` (`Cookie::build($settings, $code)` — чистая функция, как `Topbar::build`).
- Шаблон: блок в `custom/theme/ocs/template/common/footer.twig`; JS/CSS темы.
- JS API: `window.ocsConsent`, событие `ocs:consent`.

## Edge cases

- Cookies отключены в браузере → попап показывается на каждой странице, ошибок нет (запись в try/catch).
- Версия согласия увеличена → старый cookie считается невалидным, попап снова.
- Невалидный URL условий → ссылка не выводится, текст остаётся.
- Очень длинный текст → ограничение высоты, перенос, на телефоне скролл внутри попапа.
- JS выключен → попап не виден (скрыт по умолчанию), страница работает.

## Acceptance criteria

- [ ] Админ включает модуль, задаёт тексты на трёх языках и ссылку; новый посетитель видит попап.
- [ ] «Принять» и «Только необходимые» закрывают попап, ставят `ocs_consent`, после перезагрузки попапа нет.
- [ ] Увеличение версии в админке возвращает попап.
- [ ] `window.ocsConsent.get()` и событие `ocs:consent` работают.
- [ ] Десктоп и телефон выглядят цельно, не перекрывают tab bar (скриншоты).
- [ ] `npm run verify` зелёный; архив темы пересобран.
