# SPEC-085 — Доставка «Нова пошта»: справочники в БД, подсказки города и отделения в чекауте

**Status:** implemented
**Owner:** Zhuravlev Artem
**Last updated:** 2026-10-28
**Refines:** SPEC-018 REQ-INT-040/042 · **Depends on:** SPEC-004, SPEC-011, SPEC-018, SPEC-014

## Problem

Покупатель при оформлении заказа вводит город и адрес отделения «Новой пошты» руками: опечатки,
неверные номера отделений, менеджер вручную уточняет адрес. Дёргать API «Новой пошты» на каждый
ввод символа медленно и ненадёжно (лимиты, таймауты, простой API ломает чекаут).

## Purpose

Shipping-расширение `ocs_novaposhta`: области, города и отделения/почтоматы НП периодически
забираются по API в нашу БД (каждая сущность — отдельной, порционной загрузкой), а на странице
оформления заказа поле «Город» даёт подсказки городов, а поле «Адрес» — список отделений и
почтоматов выбранного города с поиском. Работает в стандартном чекауте и в Simple Checkout.

## Scope

- Расширение `custom/extensions/ocs_novaposhta/` (type `shipping`; admin + catalog; uk-ua / ru-ru / en-gb).
- Клиент API НП v2.0 поверх единого HTTP-клиента (SPEC-018 REQ-INT-010), если он есть; иначе минимальная обёртка curl с теми же таймаутами.
- Таблицы справочников, синхронизация (CLI + HTTP-вход с токеном для cron), статус синхронизации в админке.
- Автокомплит города и выбор отделения на чекауте (JS-компонент, без внешних библиотек).
- Способ доставки «Нова пошта: отделение / почтомат» в `getQuote`, запись выбранной точки в заказ.
- Совместимость со стандартным чекаутом темы (`checkout/*.twig`) и Simple Checkout.
- Пакет темы (`npm run pack:theme`), тесты на логику без сети (симулятор API).

## Out of scope

- Создание накладных (ЕН), печать этикеток, отслеживание посылок (будет отдельной спекой).
- Курьерская доставка «до двери» и адресная доставка НП (см. открытые вопросы).
- Расчёт стоимости через API (в v1 — фиксированная цена / бесплатно от суммы; см. открытые вопросы).
- Наложенный платёж/контроль оплаты, другие перевозчики.
- Правки `core/` и самого Simple Checkout (подключаемся снаружи через селекторы и события).

## Functional requirements

### Справочники и синхронизация

- **REQ-NP-001** — Три независимых справочника в БД: области (`getAreas`), города/населённые пункты (`getCities`), отделения и почтоматы (`getWarehouses`). Для каждого — собственная команда и собственное время запуска: `np-sync areas | cities | warehouses`; без аргумента — все по очереди.
- **REQ-NP-002** — Загрузка порционная и возобновляемая: страницами по ≤ 500 записей API (параметры `Page`/`Limit`), запись в БД пачками (многострочный `REPLACE INTO` — одинаково для MySQL и тестов; одна страница = один-два коротких оператора), пауза между страницами (по умолчанию 200 мс, настраивается), курсор (сущность, страница, run_id) хранится в БД — прерванный запуск продолжается с места остановки.
- **REQ-NP-003** — Идемпотентность и безопасность данных: ключ записи — `Ref` НП; запись обновляется только если изменился хеш полезных полей; строки, не пришедшие в текущем полном прогоне, помечаются `is_active = 0` (не удаляются), чтобы старые заказы и ссылки не ломались. Если полный прогон не дошёл до конца или API вернул ошибку/пусто — деактивация не выполняется.
- **REQ-NP-004** — Ограничение нагрузки на БД: размер пачки и лимит времени одного запуска настраиваются (по умолчанию пачка 500 строк, не более ~50 с на запуск для HTTP-входа; CLI — без лимита, но с паузами); запуск под `GET_LOCK` — параллельные запуски одной сущности невозможны.
- **REQ-NP-005** — Запуск раз в сутки по cron: (а) CLI `php system/library/ocs/novaposhta/bin/sync.php <entity|all> [--dry-run] [--reset]` внутри расширения (в пакете темы нет `scripts/`); (б) HTTP-вход `index.php?route=extension/ocs_novaposhta/cron&entity=…&key=<токен>` для хостингов без CLI (одна порция ≤ 50 с за вызов, повторяемый). Токен — настройка, сравнение через `hash_equals`, вход не использует данные сессии покупателя (сам запуск сессии ядром отключить нельзя). Примеры crontab — в админке.
- **REQ-NP-006** — Статус в админке: для каждой сущности — время последнего успешного прогона, число записей (активных/всего), длительность, последняя ошибка; кнопки «Обновить сейчас» (запускает порцию, не весь прогон) и «Сбросить курсор».
- **REQ-NP-007** — Каждая сущность хранит названия на двух языках API (`Description` — укр., `DescriptionRu` — рус.); выдача выбирает по языку магазина (en-gb → укр. названия).
- **REQ-NP-008** — Ошибки API (таймаут, 5xx, неверный ключ) пишутся в `ocs-http.log`/error-лог без ключа; текущие данные остаются нетронутыми; сбой не влияет на витрину (SPEC-018 REQ-INT-071).

### Чекаут: город

- **REQ-NP-010** — Поле «Город» (по умолчанию: поле `city` адреса доставки; в Simple — соответствующее поле) получает подсказки: после ≥ 2 символов, debounce ~200 мс, запрос к локальному эндпоинту, всплывающий список ≤ 10 городов вида «Київ, Київська обл.» (с областью и районом для одноимённых). Поиск по началу названия (укр. и рус.), приоритет крупных городов/областных центров.
- **REQ-NP-011** — Управление с клавиатуры (↑ ↓ Enter Esc), мышью и тачем; ARIA (`role="listbox"`, `aria-activedescendant`); закрытие по клику вне списка; подсветка совпавшей части.
- **REQ-NP-012** — При выборе города: в поле подставляется название, в скрытое поле/сессию записывается `city_ref`; по области (`area`) делается best-effort выбор региона в поле `zone_id` (сопоставление по названию с таблицей `oc_zone` Украины), а страна ставится «Украина», если она есть среди стран магазина. Если выбор региона не удался — поле не трогаем.
- **REQ-NP-013** — Если покупатель не выбрал из списка (ввёл город руками) — `city_ref` сбрасывается; чекаут не блокируется, пока не выбран способ доставки «Нова пошта» (см. REQ-NP-021).

### Чекаут: отделение / почтомат

- **REQ-NP-020** — После выбора города поле «Адрес» (`address_1`) становится полем выбора точки: при фокусе/вводе показывается всплывающее окно со списком отделений и почтоматов этого города, **с поиском** по номеру, улице, названию (подстрока, укр./рус., без учёта регистра и без различий `№`/`N`), переключатель «Все / Отделения / Почтоматы», подпись типа и режим работы, максимальный вес. Список подгружается постранично/виртуально (города с 300+ точками, напр. Київ), без заморозки интерфейса.
- **REQ-NP-021** — При выборе точки: в поле адреса подставляется «Відділення №12: вул. …, N» / «Поштомат №34030: …», `warehouse_ref` + `city_ref` + тип сохраняются в сессии (эндпоинт `select`, проверка по БД, что точка принадлежит городу и активна). При настройке «Вимагати вибір відділення» (по умолчанию да) способ «Нова пошта» показывается с пояснением «Оберіть відділення або поштомат» и **не выбирается**, пока точка не выбрана (ответ `getQuote` с `error`, работает одинаково в стандартном чекауте и Simple). События OpenCart 3 не умеют отменять действие, поэтому отдельная проверка при сохранении способа не делается.
- **REQ-NP-022** — Если покупатель правит адресное поле руками после выбора — выбор точки сбрасывается (подсказка снова открывается). Если город изменён — сбрасывается и город-зависимая точка.
- **REQ-NP-023** — Без JS и при сбое эндпоинта поле остаётся обычным текстовым (SPEC-018 REQ-INT-042). Чтобы заказ можно было оформить и в этом случае, администратор отключает «Вимагати вибір відділення»: тогда способ выбирается без точки, а менеджер видит ручной адрес (мягкая деградация — осознанный выбор администратора, а не автомат).

### Способ доставки и заказ

- **REQ-NP-030** — Shipping-расширение `ocs_novaposhta` (`shipping_ocs_novaposhta_*`): статус, сортировка, налоговый класс, гео-зона (по умолчанию Украина), цена, «бесплатно от суммы», название на каждый язык, максимальный вес/сумма (необязательно). `getQuote` отдаёт один способ «Нова пошта — відділення/поштомат»; в названии — выбранная точка, если она есть.
- **REQ-NP-031** — В заказ попадают: `shipping_city` = город НП, `shipping_address_1` = читаемая строка точки, `shipping_method` с названием точки (регион остаётся из формы; сам компонент подставляет его в форму по REQ-NP-012); `city_ref`/`warehouse_ref`/тип — в служебной таблице `oc_ocs_np_order(order_id, city_ref, warehouse_ref, type, date_added)` (для будущих накладных). Отдельный блок на странице заказа в админке не делается (нужен был бы OCMOD): точка видна в стандартных полях адреса и способа доставки.
- **REQ-NP-032** — Выбор из сессии заново проверяется по БД при каждом расчёте способов доставки (`getQuote`): если точка стала неактивной — она пропадает, способ снова требует выбора. В момент создания заказа невалидная точка в заказ не пишется, а к комментарию заказа добавляется пометка «Nova Poshta: point not confirmed».

### Совместимость

- **REQ-NP-040** — Стандартный чекаут темы (`custom/theme/ocs/template/checkout/*.twig`, оформление как гость / зарегистрированный / новый адрес): компонент подключается по настраиваемым CSS-селекторам, пресет «default» работает «из коробки» (поля `#input-shipping-city`, `#input-shipping-address-1`, `#input-payment-city` …).
- **REQ-NP-041** — Simple Checkout: пресет «simple» (селекторы полей адреса доставки/покупателя); компонент использует делегирование событий и `MutationObserver`/повторную инициализацию, т.к. Simple перерисовывает блоки AJAX-ом и пересчитывает способы доставки; значения передаются Simple стандартным способом (события `input`/`change` на полях, чтобы его собственная валидация и пересчёт сработали).
- **REQ-NP-042** — Селекторы в админке переопределяются (город, адрес, регион, страна, форма), чтобы подключить любую другую форму без правки кода; JS грузится только на страницах чекаута (`checkout/*`, `simplecheckout`).

## Non-functional requirements

- **REQ-NP-050** — Автокомплит отвечает из индексированных таблиц: запрос города < 20 мс (`name_uk`/`name_ru` с префиксным индексом, `LIKE 'xx%'`), списка точек — < 30 мс; ответ ≤ 10 городов / ≤ 50 точек за запрос; `Cache-Control: private, max-age=60` для идентичных запросов; в чекауте нет обращений к API НП.
- **REQ-NP-051** — Эндпоинты подсказок: SQL без конкатенации пользовательских данных (значения экранируются, `%`, `_`, `\` вычищаются из запроса), длина запроса ≤ 64 символов, throttle 120 запросов/мин на сессию, JSON без лишних персональных данных; HTML в ответе не используется (рендер на клиенте через `textContent`).
- **REQ-NP-052** — API-ключ НП хранится только в настройках (`shipping_ocs_novaposhta_api_key`), не в git/`.env`, не выводится на витрине и в логах (SPEC-018 REQ-INT-051).
- **REQ-NP-053** — Все изменения БД — идемпотентные миграции расширения; PHP 7.4; ничего не правится в `core/`; контроллеры тонкие, логика в `system/library/ocs/novaposhta/*`.
- **REQ-NP-054** — Локализация uk-ua / ru-ru / en-gb; доступность списка (клавиатура, фокус, контраст); стили в духе темы, без сдвигов макета.
- **REQ-NP-055** — Включение/выключение одним переключателем: при `status = 0` JS не грузится, способ доставки скрыт, cron-вход отвечает 403.

## Data requirements

Таблицы (префикс `oc_ocs_np_`, InnoDB, utf8mb4):

| Таблица | Назначение | Ключевые поля |
| ------- | ---------- | ------------- |
| `ocs_np_area` | области | `ref` PK, `name_uk`, `name_ru`, `is_active`, `run_id`, `hash` |
| `ocs_np_city` | города | `ref` PK, `area_ref`, `name_uk`, `name_ru`, `type_uk`, `region_uk`, `warehouses_count`, `is_active`, `run_id`, `hash`; индексы по `name_uk(32)`, `name_ru(32)`, `area_ref` |
| `ocs_np_warehouse` | отделения и почтоматы | `ref` PK, `city_ref`, `number`, `type` (`branch`/`postomat`/`cargo`), `type_ref`, `name_uk`, `name_ru`, `address_uk`, `address_ru`, `schedule` (JSON), `max_weight`, `lat`, `lng`, `is_active`, `run_id`, `hash`; индексы `city_ref+type+number`, FULLTEXT/префикс по названию |
| `ocs_np_sync` | курсор и статус | `entity` PK, `run_id`, `page`, `status`, `started_at`, `finished_at`, `rows_total`, `error` |
| `ocs_np_order` | точка в заказе | `order_id` PK, `city_ref`, `warehouse_ref`, `type`, `created_at` |

Настройки `shipping_ocs_novaposhta_*`: `status`, `sort_order`, `api_key`, `cron_token`, `cost`, `free_total`, `tax_class_id`, `geo_zone_id`, `title` (JSON по языкам), `selectors` (JSON), `preset` (`default`/`simple`/`custom`), `batch_size`, `pause_ms`, `max_weight`.

## Interfaces

- Admin: `extension/shipping/ocs_novaposhta` (настройки, статус и ручной запуск справочников, блок «Cron»), `…/sync` (AJAX: порция или сброс курсора).
- Catalog (JSON): `extension/ocs_novaposhta/api/config`, `…/api/cities&q=`, `…/api/warehouses&city_ref=&q=&type=&page=`, `…/api/select` (POST: город/точка в сессию), `extension/ocs_novaposhta/cron&entity=&key=`.
- CLI: `php system/library/ocs/novaposhta/bin/sync.php areas|cities|warehouses|all [--dry-run] [--reset]`.
- События: `catalog/view/common/header/before` (JS и CSS только на страницах чекаута), `catalog/model/checkout/order/addOrder|editOrder/before|after` (точка в заказ), регистрируются миграцией (SPEC-007).
- Frontend: `catalog/view/javascript/ocs/novaposhta.js` + CSS в теме; конфиг селекторов передаётся через `window.OCS_NP`.

## Edge cases

- Город без отделений -> подсказка «У цьому місті немає відділень», способ «Нова пошта» недоступен для выбора.
- Город-тёзка в разных областях -> в подсказке видна область/район; `city_ref` однозначен.
- API НП недоступно в момент cron -> данные не трогаются, ошибка в статусе, следующий запуск продолжит.
- Прерванный прогон (kill, таймаут) -> курсор позволяет продолжить; деактивации не будет, пока прогон не завершён.
- Точка закрыта (исчезла из выдачи) между выбором и заказом -> REQ-NP-032.
- Покупатель вводит город латиницей/с опечаткой -> подсказок нет, поле остаётся свободным.
- Simple перерисовал блок во время открытого списка -> список закрывается, компонент инициализируется заново, выбранное сохраняется.
- Много одновременных запросов подсказок -> throttle, ответ 429 без ошибки в консоли пользователя (список просто не открывается).
- Магазин без Украины в списке стран -> страна/регион не трогаются.

## Acceptance criteria

- [ ] `np-sync areas|cities|warehouses` заполняют таблицы раздельно; повторный запуск не плодит дубликатов и пишет только изменённое.
- [ ] Прерванный `warehouses` продолжается с курсора; деактивация происходит только после полного прогона.
- [ ] В чекауте (гость, клиент, новый адрес) при вводе «Киї» появляется список городов; выбор ставит город, регион и `city_ref`.
- [ ] После выбора города в поле адреса открывается список отделений/почтоматов с рабочим поиском по номеру и улице и фильтром типа.
- [ ] Заказ содержит город и адрес точки, а `oc_ocs_np_order` — ссылки НП; в админке заказа они видны.
- [ ] Те же сценарии проходят в Simple Checkout (после пересчёта блоков компонент не «умирает»).
- [ ] При выключенном JS/упавшем эндпоинте заказ оформляется с ручным адресом.
- [ ] Ключ API не попадает в витрину, логи и git; cron-вход без токена отдаёт 403.
- [ ] `npm run verify` зелёный; архив `dist/ocs-theme-<VERSION>.ocmod.zip` пересобран.

## Решённые вопросы (одобрено 2026-10-28, значения по умолчанию)

1. Цена в v1 — фиксированная плюс «бесплатно от суммы»; расчёт тарифа через API — отдельной спекой.
2. Только отделения и почтоматы, без курьера НП.
3. Simple Checkout: селекторы пресета «simple» составлены по принятой схеме именования полей и **не проверены** на установленной версии модуля; до проверки на живом Simple используйте «Власні селектори».
4. Способ показывается только для Украины (настройка «Лише для України», по умолчанию да).
