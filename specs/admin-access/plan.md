# PLAN — SPEC-010 Admin Access

## Approach

Roles as data (`roles.json`) provisioned by a PHP migration using the permission helper. Hardening
through one library-type extension `ocs_admin_guard` (events on admin login controller, admin model
events for audit), plus web-server level controls generated by the build.

## Decisions

| Decision | Choice | Why |
| -------- | ------ | --- |
| Password hashing | cannot change (core SHA1+salt) -> compensate (2FA, throttle, long passwords, hidden path) | editing core auth is forbidden |
| Role source | JSON in git | permissions reproducible, reviewable |
| 2FA | TOTP in extension, separate spec | non-trivial UX + recovery |
| Default API user | disabled | installer key is created at install time and widely known pattern |
| Audit | event-based tables | no core change |

## Affected files

`custom/access/*.json`, `custom/extensions/ocs_admin_guard/**`, migrations `0004_roles.php`,
`0005_api_hardening.php`, `scripts/admin-unlock.php`.

## Risks

- Route list for wildcard expansion must come from files in the built docroot, not from DB.
- Login event hooks depend on `common/login` controller structure (core upgrade review).
