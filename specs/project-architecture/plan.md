# PLAN — SPEC-001 Project Architecture

## Approach

Keep ocStore vanilla and immutable; compose it with our code at build time. The repository is
the single source of truth: code via overlay/theme/extensions/OCMOD, store configuration and
schema via ordered SQL migrations, environment via `.env`. Tooling is dependency-free Node
(`.mjs`) for file composition and verification, PHP CLI for anything that must use the store's
own DB layer or installer.

## Architecture decisions

| Decision | Choice | Why / alternatives rejected |
| -------- | ------ | --------------------------- |
| Core handling | Unmodified copy in `core/`, checksum manifest | Editing core makes upgrades impossible; git submodule/composer not offered by ocStore |
| Composition | Build step copying into `build/www` | Symlinks need admin rights on Windows; in-place overlay pollutes repo |
| Customisation order | settings > theme > extension > event > OCMOD | Weakest mechanism that works minimises upgrade breakage; vQmod rejected (obsolete, double mod systems) |
| Collision policy | Overlay may only add paths | Shadowing core files silently diverges from upstream |
| Data changes | Numbered idempotent SQL migrations + checksum | Admin-clicked config is lost on redeploy; ORM/migration framework absent in OC3 |
| Install | Run core CLI installer in place from `core/`, never ship `install/` | OC requires deleting `install/` anyway; avoids web installer exposure |
| Storage | `DIR_STORAGE` outside docroot | Official hardening; keeps logs/sessions/uploads off the web |
| Tooling language | Node `.mjs` (build/verify) + PHP (db/install) | Node present and fast for file ops; PHP needed for mysqli/installer; no Composer needed |
| Serving the build | Out of scope (no deployment spec yet) | Any web server pointed at `build/www` works; the smoke test only needs a base URL |
| Admin dir | Configurable via `ADMIN_DIR` | Obscurity layer for production at near-zero cost |
| Branching | Direct to `main` | Solo project (see memory/feedback in related repos) |

## Affected files / directories

All new: `core/` (moved), `custom/**`, `scripts/**`, `specs/**`, `docs/**`, `CLAUDE.md`,
`README.md`, `package.json`, `.env.example`, `.gitignore`.

## Risks

- ocStore 3.0.3.7 on PHP 8.2 may emit warnings or fail in places -> REQ-ARCH-003 + smoke test;
  fall back to PHP 8.0/7.4 build via `PHP_BIN` if a fatal appears.
- Core CLI installer expects certain writable paths -> installer is run against `build/www`
  after build, with config generated by us (SPEC-003); how the installer is invoked is decided by the future deployment spec.
- OCMOD refresh is normally an admin-UI action -> `scripts/refresh.php` must bootstrap the
  admin framework headlessly; if infeasible, fallback is documented manual click and a check
  that `system/storage/modification/` is non-empty.
