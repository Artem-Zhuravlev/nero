# ocStore 3.0.3.7 — internals for agents

Read this before touching anything. It describes how the platform in `core/upload/` actually
works (verified against the source in this repo; items marked **[std]** are standard OpenCart 3
behaviour not re-verified line-by-line here). Project rules on top of it are in
[SPEC-001](../specs/project-architecture/spec.md) and [agent-playbook.md](agent-playbook.md).

## 1. What it is

- **ocStore** = Ukrainian/Russian-community fork of **OpenCart 3.0.3.x** (`VERSION=3.0.3.7`,
  `VERSION_CORE=ocStore`, `VERSION_BUILD=0002`, `VERSION_LANGPACK=UK-EN-RU`).
- Procedural-ish PHP MVC-L (Model–View–Controller–Language), **no Composer app, no PSR-4, no DI
  container, no ORM, no migration framework**. Templates are **Twig**. DB is MySQL/MariaDB via
  `mysqli` (also `mpdo`, `pgsql` drivers present).
- ocStore additions over vanilla OC: built-in **blog** (`blog_category`, `article*` tables,
  `catalog/controller/blog`, modules `blog_*`, `featured_article`), built-in **SeoPro**
  (`system/library/seopro.php`, flag `config_seo_pro`), `translation` table/event,
  `startup/sass` (SCSS compile), OpenCartForum marketplace controller, UK/RU/EN language packs,
  admin "hide modules" per user group, default language `uk-ua`.
- Minimum PHP is enforced in `system/startup.php`: **>= 7.3**. Core was written for PHP 7.x
  (8.x may emit deprecations).

## 2. Directory map (`core/upload/`)

```
index.php            storefront entry   -> start('catalog')
admin/index.php      admin entry        -> start('admin')
config.php           GENERATED by installer (config-dist.php files are EMPTY, 0 bytes)
admin/config.php     GENERATED by installer
.htaccess.txt        rename to .htaccess (SEO rewrite + deny rules)
install/             web + CLI installer (cli_install.php), opencart.sql — delete after install
system/              framework (shared by catalog & admin)
  startup.php        bootstrap helpers, autoloader, start()
  framework.php      the request lifecycle (section 3)
  engine/            action, controller, event, loader, model, proxy, registry, router
  config/            default.php, catalog.php, admin.php (+ install, paypal*, googleshopping)
  library/           classes autoloaded by namespace/path (cache, cart, db, session, mail,
                     template/twig, url, language, request, response, seopro, …)
  helper/            general.php, utf8.php, HTMLPurifier (functions, loaded explicitly)
  storage/           DIR_STORAGE default: cache, logs, session, upload, download,
                     modification (OCMOD output), vendor (Twig, ScssPhp… autoload.php)
  modification.xml   built-in OCMOD that makes core include files via modification()
catalog/             storefront application
  controller/ model/ language/ view/{theme/default/{template,stylesheet,image},javascript}
admin/               admin application (same shape; view/template, view/javascript, view/stylesheet)
image/               public images (catalog/ = product uploads, cache/ = thumbnails, payment/)
```

`DIR_CONFIG`, `DIR_CACHE`, `DIR_DOWNLOAD`, `DIR_LOGS`, `DIR_MODIFICATION`, `DIR_SESSION`,

## 3. Request lifecycle (`system/framework.php`)

1. `index.php` defines version, includes `config.php`; if `DIR_APPLICATION` undefined ->
   redirects to `install/`. Includes `system/startup.php`, calls `start('catalog'|'admin')`.
2. `startup.php`: error level, timezone, `$_SERVER` normalisation, defines
   **`modification($file)`** (returns the OCMOD-patched copy from `DIR_MODIFICATION` if one
   exists), registers **autoloader** (`Foo\Bar` -> `system/library/foo/bar.php`, lower-cased,
   always passed through `modification()`), requires engine classes, helpers, optional
   `DIR_STORAGE/vendor/autoload.php`.
3. `framework.php`:
   `Registry` -> `Config` (load `default.php`, then `catalog.php` or `admin.php`) -> `Log` ->
   PHP error handler -> `Event` (registers `action_event` from config) -> `Loader` -> `Request`
   -> `Response` -> `DB` (if `db_autostart`) -> `Session` -> `Cache` -> `Url` -> `Language`
   -> `Document` -> autoloads (config/language/library/model lists) -> `Router`
   -> **pre-actions** -> **dispatch** default route -> `$response->output()`.
4. **Pre-actions** (controllers run before every request, in order):
   - catalog: `startup/session`, `startup/startup`, `startup/error`, `startup/event`,
     `startup/maintenance`, `startup/seo_url`
   - admin: `startup/startup`, `startup/error`, `startup/event`, `startup/sass`, `startup/login`,
     `startup/permission`
   - `startup/startup` (catalog) resolves the **store** by host (`oc_store`), loads **all
     `oc_setting` rows** (store 0 + current) into `$this->config`, picks language/currency/
     customer/cart/tax/affiliate, so `config_*` and `module_*`/`payment_*` keys are available.
   - `startup/event` loads enabled rows of **`oc_event`** into the Event registry.
   - `startup/seo_url` (catalog) rewrites `_route_` to `route` + ids via `oc_seo_url`
     (SeoPro hooks inside when `config_seo_pro`).
5. **Router**: runs pre-actions (any returning an `Action` replaces the target), then follows
   `Action` chains until a controller returns nothing. Default route: `common/home` (catalog) /
   `common/dashboard` (admin); 404: `error/not_found`.

## 4. Engine primitives

- **Registry**: key/value container; `$this->config`, `$this->db`, `$this->load`, `$this->request`,
  `$this->response`, `$this->session`, `$this->cache`, `$this->url`, `$this->language`,
  `$this->document`, `$this->event`, `$this->customer`/`cart`/`tax`/`currency`/`user`
  (set by startup controllers), and `$this->model_<route_with_underscores>` are all reachable
  via `Controller::__get` / `Model::__get`.
- **Route** `a/b/c`: `Action` searches `controller/a/b/c.php` then `controller/a/b.php` method
  `c` (last segment becomes method; default `index`). Class name `Controller` + route without
  non-alphanumerics, **case-insensitive in practice**: `extension/module/featured` ->
  `ControllerExtensionModuleFeatured`. Methods starting `__` are refused.
- **Loader** (`$this->load->…`): `controller($route,$data)` (returns rendered child output),
  `model($route)` (-> `$this->model_a_b`, wrapped in a `Proxy` so every method fires
  `model/<route>/<method>/before|after`), `view($route,$data)` (Twig render), `language($route)`,
  `library($route)` (class = route with `\\`, file `system/library/<route>.php`, registered under
  `basename`), `helper($route)`, `config($file)`.
- **Event system** — trigger string `<type>/<route>/<before|after>` where type is
  `controller`, `model`, `view`, `language`. Triggers support `*` and `?` wildcards and are
  prefix-matched. Handler signature uses references: `function(&$route, &$args[, &$output])`.
  `before` handlers returning a non-null value **short-circuit** the original call.
  Registration: (a) in config `action_event` (core only, forbidden for us), (b) rows in
  **`oc_event`** (`code`, `trigger`, `action`, `status`, `sort_order`; table is MyISAM).
  `oc_event.trigger` is stored with an app prefix and the prefix is stripped on load:
  `catalog/model/account/customer/addCustomer/after` (storefront) or
  `admin/view/common/header/before` (admin). `action` is a route: `extension/ocs_x/handler`
  or `extension/ocs_x/handler/method`.
- **Template**: `Template('twig')`; `DIR_TEMPLATE . $route . '.twig'`. Twig is configured with
  **`autoescape => false`** in this core -> templates do NOT escape automatically; escape in the
  controller (`htmlspecialchars`) or with `|escape` explicitly. Cache dir `DIR_CACHE/template/`.
- **Language**: `language->load('a/b')` merges `language/<code>/a/b.php` arrays (`$_['key']`)
  over the default; missing keys return the key itself. Admin/Catalog have independent
  language trees. `oc_translation` + `event/translation` allow DB-level overrides per language.
- **Config values**: `$this->config->get('config_name')`. Setting rows with `serialized=1` are
  JSON-decoded.
- **Response/Request**: `request->get|post|cookie|files|server` are pre-sanitised
  (`htmlspecialchars`) copies — still escape/cast at the point of use for SQL.
- **DB**: `$this->db->query($sql)` returns object with `->row`, `->rows`, `->num_rows`;
  `escape()`, `getLastId()`, `countAffected()`. No prepared statements; build SQL with
  `DB_PREFIX` and `escape()`/`(int)`.

## 5. Storefront controller anatomy (typical)

```php
class ControllerProductCategory extends Controller {
  public function index() {
    $this->load->language('product/category');         // adds keys to $this->language
    $this->load->model('catalog/category');             // $this->model_catalog_category
    $this->document->setTitle(...);                     // <title>, meta, scripts, styles
    $data['x'] = ...;
    $data['header'] = $this->load->controller('common/header');   // layout children
    $this->response->setOutput($this->load->view('product/category', $data));
  }
}
```

Common children controllers: `common/header|footer|column_left|column_right|content_top|
content_bottom|cart|search|menu`. **Layouts** (`oc_layout`, `oc_layout_route`, `oc_layout_module`)
map a route (e.g. `product/category`) to positions (`content_top`, `column_left`, …) filled with
modules; `common/column_left` etc. look up the layout by route and render each
`extension/module/<code>` (module instances in `oc_module`, serialized settings).

Main route groups: `common/*`, `product/*` (category, product, search, manufacturer, compare,
special), `checkout/*` (cart, checkout, confirm, success…), `account/*`, `affiliate/*`,
`information/*` (contact, sitemap, information), `blog/*`, `api/*`, `extension/{module,payment,
shipping,total,feed,…}/*`, `event/*`, `startup/*`, `mail/*`, `tool/*`.

## 6. Admin

- Access requires `user_token` GET param (session-bound) on every URL; `startup/login`
  enforces it, `startup/permission` checks **`access`** on the route against the user group's
  JSON permission lists (`oc_user_group.permission` with `access` and `modify` arrays of routes).
  Controllers must additionally call `$this->user->hasPermission('modify', $route)` before
  writes. For 3-segment extension routes (`extension/module/featured`) the permission route is
  the full 3 segments.
- Admin menu: `admin/controller/common/column_left.php` (core file; extend via OCMOD or
  event on `admin/view/common/column_left/before` — [std]).
- Extension management: `marketplace/extension?type=<type>` lists extensions of a type,
  files are discovered from `admin/controller/extension/<type>/*.php`;
  **install** inserts `oc_extension (type, code)`, grants permissions to the user group,
  then calls the extension's `install()` method if it exists; **uninstall** removes the row and
  calls `uninstall()`. Settings are stored in `oc_setting` under `code=<type>_<name>`,
  `key=<type>_<name>_<field>` (e.g. `module_featured_status`, `payment_cod_status`) edited
  via `setting/setting->editSetting($code, $data)`.
- Extension types: `advertise analytics captcha currency dashboard feed fraud module payment
  report shipping theme total` (+ `extension/extension/*` list controllers).
- **Modules** are special: a module extension may have many instances stored in `oc_module`
  (`name`, `code`, serialized `setting`); instances are placed into layouts.
- Admin has its own `model/` (`catalog/product` etc.), `view/template`, `view/javascript`,
  `view/stylesheet`; the Twig engine and event system are the same.

## 7. Extension anatomy (installable via admin or deployed as files)

Install package `*.ocmod.zip` layout (marketplace/installer): `upload/` (files copied to the
site root), `install.xml` (an OCMOD), optional `install.php`, `install.sql`. In this repo we
do **not** use the admin installer; the build copies `upload/` trees and migrations register
rows (see SPEC-001).

Payment extension needs: admin controller+language+twig (settings: status, geo zone, order
status, sort order), catalog controller `extension/payment/<code>` (`index()` renders button;
`confirm()` finalises order via `checkout/order->addOrderHistory`), catalog model
`extension/payment/<code>->getMethod($address,$total)` returning method array. Shipping:
catalog model `extension/shipping/<code>->getQuote($address)`. Order total:
catalog model `extension/total/<code>->getTotal($total)` (`$total['totals'][]`, `['total']`,
`$taxes`) with `sort_order` setting.

## 8. Themes

- Theme directory: `catalog/view/theme/<name>/{template,stylesheet,image}`; JS shared in
  `catalog/view/javascript/` (theme folder `javascript` also allowed).
- Selection: setting `config_theme=<name>`; the theme must be an installed `theme` extension
  with `theme_<name>_status=1` (`event/theme` exits with an error otherwise; for `default` the
  directory comes from `theme_default_directory`).
- Resolution (`catalog/controller/event/theme.php`, fires on `view/*/before`): if
  `<theme>/template/<route>.twig` exists use it, else **fall back to `default/template/`**. A
  DB-stored override (`oc_theme`, admin "Theme Editor") wins unless OCMOD produced a file.
  => A custom theme only needs the templates it changes.
- `startup/sass` compiles `catalog/view/theme/<name>/stylesheet/*.scss` -> `.css`
  (ScssPhp in `system/storage/vendor`) when `developer_sass` is off or CSS missing.
- Twig `{% include %}` resolves from `DIR_TEMPLATE`; use theme-relative paths.
- Template variable conventions: `{{ header }}`, `{{ column_left }}`, `{{ content_top }}`,
  `{{ content_bottom }}`, `{{ footer }}`, language strings as `{{ text_xxx }}` / `{{ button_xxx }}`
  injected by the controller (`$data[...]= $this->language->get(...)` or loop on
  `$this->language->all()` in some modules).

## 9. OCMOD (the patch system)

- XML modification files stored in `oc_modification`; admin "Refresh" (`marketplace/modification
  /refresh`) rebuilds **patched copies** of every affected file into
  `DIR_MODIFICATION` (`system/storage/modification/{admin,catalog,system}/…`). At runtime the
  `modification($file)` function (and Twig patch in `system/modification.xml`) makes PHP/Twig
  load the patched copy instead of the original. **Core files on disk are never changed.**
- Structure: `<modification><name/><code/><version/><author/><link/><file path="…">
  <operation><search [regex|trim|index]>…</search><add position="replace|before|after|top|
  bottom|ibefore|iafter" [offset]>…</add></operation></file></modification>`.
  `<file path>` accepts globs/braces; `error="skip|log|abort"` controls missing matches.
- After any change to OCMOD files **or to core/extension PHP that an OCMOD patches**, refresh
  modifications and clear cache or the old patched copy is used. Stale files in
  `system/storage/modification/` are the #1 cause of "my edit does nothing".
- The default `system/modification.xml` (code `default`) is what makes the whole mechanism work;
  never disable it.

## 10. Database

- Prefix `DB_PREFIX` (default `oc_`). Engine mix: core tables InnoDB (mostly) / MyISAM
  (`oc_event`, etc.); charset `utf8`/`utf8_general_ci`.
- Groups (from `install/opencart.sql`): **catalog** (`product`, `product_description`,
  `product_to_category`, `product_image/option/option_value/attribute/discount/special/
  related/filter/reward/recurring/to_store/to_layout/to_download`, `category`,
  `category_description`, `category_path`, `category_filter`, `category_to_store/layout`,
  `manufacturer*`, `attribute*`, `option*`, `filter*`, `download*`, `review`, `information*`),
  **blog** (`blog_category*`, `article*`, `article_to_blog_category`, `review_article`,
  related tables), **sales** (`order`, `order_product/option/total/history/voucher/
  recurring*/shipment`, `order_status`, `shipping_courier`, `cart`, `coupon*`, `voucher*`,
  `return*`), **customers** (`customer`, `customer_group*`, `address`, `customer_activity/ip/
  login/online/reward/transaction/search/wishlist/history/approval`, `custom_field*`),
  **config** (`setting`, `store`, `language`, `currency`, `country`, `zone`, `geo_zone`,
  `zone_to_geo_zone`, `tax_class/rate/rule`, `weight_class*`, `length_class*`, `stock_status`,
  `layout*`, `module`, `extension`, `extension_install`, `extension_path`, `modification`,
  `event`, `seo_url`, `theme`, `translation`, `upload`, `banner*`, `marketing`), **admin**
  (`user`, `user_group`, `api*`), `session`, `statistics`, `googleshopping_*`.
- `oc_setting(setting_id, store_id, code, key, value, serialized)`; **all runtime config comes
  from here** (store 0 = global). `oc_seo_url(store_id, language_id, query, keyword)` holds
  slugs (`product_id=42`, `category_id=20`, `information_id=4`, `manufacturer_id=…`, or a route).
- Multi-language content tables follow `<entity>` + `<entity>_description(<id>, language_id, …)`.
- Multi-store: `oc_store`, `*_to_store` link tables, `store_id` in settings.
- No foreign keys. Deleting an entity means deleting from every related table in model code.
- Sessions in DB (`session_engine = db`).

## 12. Known pitfalls

1. `config-dist.php` is empty; `config.php` only exists after install and holds secrets —
   never commit it.
2. `system/storage` inside the docroot is insecure; production moves `DIR_STORAGE` outside.
3. OCMOD output cached in `DIR_MODIFICATION`; always refresh after changes.
4. Twig autoescape is **off**: escape output yourself.
5. Model methods are called through `Proxy` — you cannot call `parent::` or private helpers of
   another model through `$this->model_*`; share code via a library.
6. `oc_event` is MyISAM and unversioned: an event registered with a wrong trigger fails
   silently. Verify with a log line when adding.
7. `Action` resolution is route-greedy: `a/b/c` prefers `controller/a/b/c.php`, else treats `c`
   as a method of `controller/a/b.php`. Avoid method names that match sub-files.
8. Core is full of `$this->request->get` raw-ish values; always `(int)` IDs in SQL.
9. SeoPro (`startup/seo_url`) rewrites `route`; if routes behave oddly check `config_seo_pro`
   and `oc_seo_url`.
10. PHP >= 8 deprecations (e.g. dynamic things, `each`, implicit float->int) may log noise;
    don't "fix" core — configure error reporting.
11. **Two different "language codes".** `$this->language->get('code')` is the HTML code from the language
    file (`uk`, `en`), while the language *directory* / `oc_language.code` is `uk-ua` / `en-gb` and is in
    `$this->config->get('config_language')`. Per-language settings keyed by language code must use
    `config_language` (found in the first live run of SPEC-031: announcement and links were empty).
12. **`$disallow_params` core bug.** `catalog/controller/product/{category,search,manufacturer_info,special}.php`
    use `in_array('sort', $disallow_params, true)` but define it only when `config_noindex_disallow_params`
    is non-empty: any request with `sort`, `order`, `page` or `limit` logs a Notice + Warning (TypeError on
    PHP 8). Migration `0003_noindex_disallow_params` sets it to `page`.
13. The default `config_timezone` is `Europe/Kyiv`, unknown to older PHP tz databases (PHP 7.4.33 Windows
    build): a Notice per request in the log. Harmless; update tzdata or set `Europe/Kiev` in the admin.
